rpyc-async

An asyncio-native fork of RPyC (Remote Python Call), a library for symmetric remote procedure calls between Python processes. Clients call remote methods with await, servers can be written with async def, and either side can await a call back into the other over the same connection.

pip install rpyc-async · Python 3.10+ · import name rpyc_async

Project status

rpyc-async 1.1.0 is a young project: its repository was created in July 2026, and it is developed actively. It is forked from RPyC 6.0.1 and runs in production inside deep-worker, where the agent processes serve their calls through it. The distribution is separate from upstream and can be installed next to rpyc in the same environment.

What it adds to RPyC

  1. The server can call back into an idle client and get an answer. The client does not have to be busy. A callback can also call the server again, several levels deep. In upstream RPyC the callback runs only when the client next waits for a result. If the server gives up first, the call times out. 
    # server: ask the client for a value, then use it
async def exposed_process(self, callback, value):
    return await callback(value * 2)
  2. Use async and await on both sides. Many calls can wait at the same time on one connection, without a thread for each one. 
    # upstream: blocks until the answer arrives
result = conn.root.double(21)

# rpyc-async: other work runs while this waits
result = await conn.root.double(21)
  3. On the asyncio API, an idle connection does nothing. No timer wakes up to check it. Upstream's thread-pool server checks idle connections ten times a second.
  4. Remote objects are released when you let go of them. On the asyncio API, when you drop your last reference to a remote object, the server is told to release it. Releases are sent in batches, and the server confirms them.
  5. Objects keep their ids while they exist. Each object gets an id for the connection that is not reused while the object lives. Upstream uses Python's memory address, which can be reused once an object is freed.
  6. Closing does not block, and blocking calls are refused inside async code. await conn.aclose() closes the connection without blocking the event loop. Calling a blocking function from inside async code raises an error instead of hanging. 
    # inside async code
rpyc.connect("localhost", 18861)   # RuntimeError: use async_connect() with await

Example

Server (server.py):

import asyncio
from rpyc_async import AsyncioServer, Service

class MyService(Service):
    async def exposed_double(self, x):
        await asyncio.sleep(0.1)
        return x * 2

async def main():
    server = AsyncioServer(MyService, port=18871)
    await server.start()
    await asyncio.sleep(8)

asyncio.run(main())

Client (client.py), run while the server is up:

import asyncio
import rpyc_async as rpyc

async def main():
    conn = await rpyc.async_connect("localhost", 18871)
    try:
        print(await conn.root.double(21))
    finally:
        await conn.aclose()

asyncio.run(main())

Expected output on stdout: 42. The library also writes one INFO line per connection to stderr.

Relationship to upstream RPyC

rpyc-async is forked from RPyC 6.0.1 and versioned independently (current release 1.1.0). It is a separate distribution, not a drop-in replacement for classic synchronous RPyC: the API centres on async_connect() and AsyncioServer, and both peers must run rpyc-async. Both can be installed in the same environment as upstream rpyc.

Installation

pip install rpyc-async

Requires Python 3.10 or later. The PyPI classifiers list Linux and POSIX as the operating systems.
